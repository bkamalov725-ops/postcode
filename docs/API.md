# XML API оценки загрузки

Сервис принимает фото и строковый номер перевозки, вычисляет загрузку в процентах,
сохраняет результат в SQLite и возвращает XML. Используется тот же `Predictor`, что
и в `scripts/predict_attention518.py`. Базовый энкодер создаётся один раз при запуске;
при каждом прогнозе в него последовательно загружаются пять обученных частей. Интернет не используется. Если веса отсутствуют
или несовместимы, запуск завершается ошибкой; подмена модели baseline не выполняется.

## Запуск

```bash
python serve.py --bundle-dir runtime/attention518 --db-path runtime/assessments.sqlite3 --device cpu --threads 4 --host 127.0.0.1 --port 8000
```

Папка bundle должна содержать `MODEL_MANIFEST.json`, `plan.json`, `highres/encoder`,
пять папок `primary/fold0`–`primary/fold4` и исходники `postcode_ml`.
Она создаётся командой `python scripts/install_attention518.py` после `git lfs pull`.
Bundle считается доверенным артефактом команды; его нельзя
принимать от внешнего пользователя. Для контейнера файлы модели и каталог базы
подключаются постоянными томами согласно инструкции в README.

Аргументы можно заменить переменными `POSTCODE_BUNDLE_DIR`, `POSTCODE_DB_PATH`,
`POSTCODE_DEVICE`, `POSTCODE_THREADS` и `PORT`. По умолчанию используются значения
из команды выше. Один процесс сервиса держит одну модель в памяти. Обработка
изображения выполняется в рабочем потоке, а вызовы общего предиктора сериализуются
внутри него. При параллельных запросах время ответа включает ожидание модели.
Эндпоинт здоровья и чтение истории не требуют запуска нейросети.
По умолчанию сервер доступен только с этого компьютера. В контейнере
Docker используется явный `--host 0.0.0.0` для подключения к опубликованному порту.

## Создание оценки

`POST /assessments`

Заголовок: `Content-Type: application/xml`. Также принимается `text/xml`.
XML без пространств имён, DTD и сущностей. Нужны ровно два элемента:

```xml
<?xml version="1.0" encoding="utf-8"?>
<assessment>
  <shipment_id>00123</shipment_id>
  <image encoding="base64">BASE64_BYTES_OF_JPEG_OR_PNG</image>
</assessment>
```

`BASE64_BYTES_OF_JPEG_OR_PNG` нужно заменить Base64 исходных байтов фотографии
без префикса `data:image/...`. Пробелы и переносы строк в Base64 допускаются.
Фото передаётся внутри XML; загрузки по URL и multipart в этом MVP нет.
`shipment_id` — строка длиной 1–128 символов: буквы, цифры, `_`, `.`, `:`, `-`.
Пробелы по краям удаляются, ведущие нули сохраняются. Неизвестные поля,
повторяющиеся элементы и лишние атрибуты отклоняются.

Ограничения: тело XML не более **16 MiB**, изображение после Base64-декодирования
не более **10 MiB**, разрешение не более **20 000 000 пикселей**. Поддерживаются
JPEG и PNG; проверяется реальный формат и декодирование изображения.

Пример успешного ответа **201 Created**:

```xml
<?xml version='1.0' encoding='utf-8'?>
<assessment>
  <assessment_id>22608bea-6694-4a8c-8adc-b1b830b0b0ac</assessment_id>
  <shipment_id>00123</shipment_id>
  <load_pct>73.25</load_pct>
  <model_version>VERSION_FROM_LOADED_BUNDLE</model_version>
  <created_at>2026-09-18T10:00:00.123Z</created_at>
  <processing_ms>1523.4</processing_ms>
</assessment>
```

Значения в примере иллюстративные; время не является результатом измерения.
`load_pct` — конечное число от 0 до 100. `model_version` идентифицирует загруженный
bundle. Время `created_at` записывается в UTC. `processing_ms` включает получение
тела запроса приложением, проверку изображения, ожидание и прогнозирование;
не включает запись результата в SQLite, отправку ответа и сетевую задержку клиента.

Каждый успешный POST, включая повтор той же фотографии для того же номера,
создаёт **новую запись** с отдельным UUID. Повтор запроса не идемпотентен.
История не перезаписывается. Если требуется повторно получить результат,
используйте GET. База сохраняет SHA-256 фотографии, но сами фотографии
не сохраняются: временный файл удаляется после прогноза, в том числе при ошибке.

## Получение сохранённых результатов

`GET /shipments/00123` — последняя сохранённая оценка, статус **200** и элемент
`assessment` в том же формате, что выше. «Последняя» определяется порядком записи
в базу, включая случаи одновременных запросов. При отсутствии записей — **404**.

`GET /shipments/00123/history?limit=100` — история от новых записей к старым.
`limit` по умолчанию 100, допустимо 1–1000. Пример структуры ответа **200**:

```xml
<assessments shipment_id="00123" count="2">
  <assessment><!-- все поля первой оценки --></assessment>
  <assessment><!-- все поля второй оценки --></assessment>
</assessments>
```

`count` — число записей в этом ответе; история ограничивается `limit`.
При отсутствии записей — **404**. GET не запускает модель. История сохраняется
после перезапуска при использовании того же файла SQLite. При удалении контейнера
без постоянного тома его локальная база будет потеряна.

`GET /health` — **200**, когда стартовая загрузка модели и базы завершилась:

```xml
<health><status>ready</status><model_version>VERSION_FROM_LOADED_BUNDLE</model_version></health>
```

Health проверяет завершение инициализации; он не является тестом нейросети на
каждом запросе и не выполняет запись в базу.

## Ошибки

Ошибки приложения, маршрутизации и параметров возвращаются в XML:

```xml
<error>
  <code>invalid_image</code>
  <message>Image is damaged or cannot be decoded.</message>
</error>
```

| HTTP | Ситуация |
|---|---|
| 400 | Ошибочный XML, запрещённые DTD/сущности, неизвестные или повторные поля, некорректный ID, Base64, повреждённое изображение |
| 404 | Перевозка или маршрут отсутствует |
| 405 | HTTP-метод не поддерживается маршрутом |
| 413 | Превышен размер XML, байтов изображения или число пикселей |
| 415 | Content-Type не XML или распознанный формат изображения не JPEG/PNG |
| 422 | Некорректный `limit` истории |
| 500 | Внутренняя ошибка модели или хранения; подробности только в серверном логе |

Модельные `NaN`, бесконечность и значения вне `[0, 100]` не записываются в базу.
На ошибочные входные данные прогноз не запускается. Технические ошибки самого
HTTP-сервера до передачи запроса приложению, например повреждённый HTTP, находятся
вне XML-контракта приложения.

## Пример клиента Python

Готовый клиент из репозитория:

```bash
python scripts/submit_photo.py --image photo.jpg --shipment-id 00123 --url http://127.0.0.1:8000
```

Используется только стандартная библиотека; сервер должен уже работать.

```python
import base64
from pathlib import Path
from urllib.request import Request, urlopen
from xml.etree import ElementTree as ET

root = ET.Element("assessment")
ET.SubElement(root, "shipment_id").text = "00123"
ET.SubElement(root, "image", encoding="base64").text = base64.b64encode(
    Path("photo.jpg").read_bytes()
).decode("ascii")
request = Request(
    "http://127.0.0.1:8000/assessments",
    data=ET.tostring(root, encoding="utf-8", xml_declaration=True),
    headers={"Content-Type": "application/xml"},
    method="POST",
)
with urlopen(request, timeout=120) as response:
    print(response.read().decode("utf-8"))
with urlopen("http://127.0.0.1:8000/shipments/00123", timeout=10) as response:
    print(response.read().decode("utf-8"))
```

Для подготовленного `request.xml`:

```bash
curl -H "Content-Type: application/xml" --data-binary @request.xml http://127.0.0.1:8000/assessments
curl http://127.0.0.1:8000/shipments/00123/history
```

В PowerShell используйте `curl.exe` для этих команд. Сервис предназначен для
локального запуска или защищённой сети: пользовательская авторизация и управление
доступом в текущий MVP не входят.
