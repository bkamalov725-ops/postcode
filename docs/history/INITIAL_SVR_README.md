# Оценка загрузки транспорта по фотографии

> **Финальная версия: Attention518.** Актуальные запуск, веса, XML API, воспроизведение и ограничения — в [FINAL_SERVICE.md](FINAL_SERVICE.md).
> Разделы ниже сохраняют историю первоначального DINO + SVR решения; их метрики не относятся к финальной модели.

Сервис для Postcode Challenge оценивает заполнение кузова от 0 до 100 по фотографии,
сохраняет результат с номером перевозки и возвращает XML. Целевая величина —
экспертная оценка размещённого груза, условно по занятой площади пола.
Масса, грузоподъёмность и план размещения груза не вычисляются.

Реализованы офлайн-прогноз, XML API, история оценок в SQLite, подготовка данных,
повторное обучение регрессора и генерация проверенного `submission.csv`.
Модель сервиса загружается один раз при старте. Обучение и сервис используют
одинаковую обработку изображений: кадр сохраняет пропорции и не обрезается.

## Проверенное качество

Успешный запуск на Kaggle: Python 3.12, две Tesla T4, 716 train, 307 test.
Проверка на пяти частях с сохранением групп похожих фотографий:

| Метод | MAE, п.п. | Доля ошибок ≤ 10 п.п. |
| --- | ---: | ---: |
| Исходные признаки + Ridge | 18,09 | 37,85% |
| DINOv2 ViT-B/14, пространственные признаки + SVR | **8,98** | **64,39%** |

Это локальная проверка для выбора модели, а не результат скрытого теста.
Нейросетевой энкодер фиксирован; обучается регрессор. Проверенный ансамбль
DINOv2 + ConvNeXt уступил лучшему DINOv2, поэтому сервис использует только DINOv2.
Метрики: [validation/metrics_kaggle.json](validation/metrics_kaggle.json).

## Локальный запуск

Команды выполняются из корня этого репозитория. Рекомендуется **Python 3.12**:
регрессор обучен с scikit-learn 1.6.1. Используйте согласованные зависимости
из `requirements-cpu.txt`.

Windows PowerShell:

```powershell
python -m venv .venv-cpu
.\.venv-cpu\Scripts\python.exe -m pip install torch==2.10.0 torchvision==0.25.0 --index-url https://download.pytorch.org/whl/cpu
.\.venv-cpu\Scripts\python.exe -m pip install -r requirements-cpu.txt
.\.venv-cpu\Scripts\python.exe scripts/prepare_model.py --archive ../postcode_model.zip --output runtime/model_bundle --trust-model-source
.\.venv-cpu\Scripts\python.exe serve.py
```

В первой команде `python` должен указывать на установленный Python 3.12.
Если окружение и веса уже подготовлены, достаточно последней команды.
Адрес сервиса: `http://127.0.0.1:8000`. Готовность: `GET /health`.
Контракт, ответы и ошибки: [docs/API.md](docs/API.md).

`postcode_model.zip` — результат собственного обучающего запуска команды.
Импортёр сверяет контрольные суммы и извлекает только выбранные энкодеры.
`--trust-model-source` подтверждает известный источник: bundle содержит pickle
и Python-код. Модели от посетителей API не принимаются.

## Одна фотография и история

В другом терминале, пока сервис работает:

```powershell
.\.venv-cpu\Scripts\python.exe scripts/submit_photo.py --image "C:\path\to\photo.jpg" --shipment-id "000123"
curl.exe http://127.0.0.1:8000/shipments/000123
curl.exe http://127.0.0.1:8000/shipments/000123/history
```

Каждый POST создаёт новую оценку и сохраняет предыдущие. GET возвращает последнюю
сохранённую оценку без запуска нейросети. Номер перевозки — строка, нули сохраняются.
В базе остаются результат, версия модели, дата, время обработки и SHA-256 фото.
Фотография после обработки удаляется. База `runtime/assessments.sqlite3`
сохраняется между перезапусками.

Принимаются JPEG/PNG до 10 МиБ и 20 мегапикселей; XML до 16 МиБ. Ошибки возвращаются
в XML. Во время прогноза доступны история и health. Прогнозы обслуживаются
последовательно одним экземпляром модели; очередь увеличивает время ответа.

## Данные и submission.csv

Для участника команды с нашим архивом данных:

```powershell
.\.venv-cpu\Scripts\python.exe scripts/prepare_data.py --archive ../kaggle_launch/postcode_dataset.zip --output data
.\.venv-cpu\Scripts\python.exe make_submission.py --test-csv data/test/test.csv --images-dir data/test/images --output outputs/submission_cpu.csv
```

Импортёр понимает архив `train/...`, `test/...` и старый формат
`postcode/train/...`, `postcode/test/test/...`. Он проверяет таблицы и фотографии
до публикации. Отличающиеся существующие файлы не перезаписываются.
Для исходного расположения файлов в нашем рабочем каталоге распаковка не нужна:

```powershell
.\.venv-cpu\Scripts\python.exe make_submission.py --test-csv ../test/test/test.csv --images-dir ../test/test/images --output outputs/submission_cpu.csv
```

Генератор загружает модель один раз, обрабатывает по четыре фото и требует
307 уникальных ID и конечные значения `[0,100]`. Итоговый CSV проверяется до
замены файла; при ошибке прежний CSV сохраняется. Колонки: `image_id,load_pct`.
CPU и GPU могут давать небольшие численные различия. Исходный Kaggle submission
не перезаписывается.

## Обучение и воспроизводимость

[Инструкция Kaggle](docs/KAGGLE_RU.md) описывает запуск на двух GPU.
Метки test скрыты; числа в шаблоне ответа не являются разметкой.
Копия test внутри исходного baseline неполная и не используется.

Для сравнения экспериментов сохранено разбиение успешного запуска:
`validation/folds_kaggle.csv`. Одинаковый seed с разными версиями scikit-learn
может дать разные части.

```bash
python run_experiment.py --data-root ../ --output outputs/repeat --encoders dinov2_vitb14 convnext_tiny --folds-csv validation/folds_kaggle.csv
```

Команда рассчитана на GPU; для запуска на CPU добавьте `--allow-cpu`.
Обновлённый Kaggle-ноутбук уже включает этот файл и передаёт его автоматически.
Проверяются ID, метки, группы и отсутствие пересечения групп между частями.
Источник и SHA-256 разбиения попадают в отчёт. Стандартизация и обучение
регрессора выполняются только на обучающей части каждого разбиения.

Для повторного обучения на подтверждённых новых фото подготовьте отдельную копию
данных: добавьте фото, строки `image_id,load_pct` в `train.csv` и группы в
`train_groups.csv`. ID должны быть уникальными, разметка — подтверждённой человеком.
Похожие фото сохраняйте в одной группе. Оставьте штатный test. Пример для 720 train:

```bash
python run_experiment.py --data-root data_extended --expected-train 720 --output outputs/retrain_720 --encoders dinov2_vitb14
```

Переобучается регрессор, веса энкодера остаются фиксированными. Старое разбиение
на 716 фото здесь неприменимо. Для повторения расширенного эксперимента передайте
его сохранённый `folds.csv`. Новую проверенную модель импортируйте в отдельную папку
и перезапустите сервис с `--bundle-dir` на неё.

Запуск сохраняет метрики, прогнозы валидации, разбиения, ошибки, признаки,
исходники, версии зависимостей, CSV, `postcode_results.zip` и `postcode_model.zip`.
Данные и веса не добавляются в Git. Модель нужно отдельно передать проверяющим
или предоставить доступ к весам, как допускает задание.

## Docker

Сначала подготовьте `runtime/model_bundle`, затем в PowerShell:

```powershell
docker build -t postcode-api .
docker run --rm -p 127.0.0.1:8000:8000 --mount "type=bind,source=$((Get-Location).Path)/runtime,target=/app/runtime" postcode-api
```

Каталог `runtime` содержит веса и постоянную базу; bind mount обязателен.
В образ включается только код, используются CPU-зависимости. CI/CD не применяется.
Сборку нужно отдельно проверить на машине с Docker: на текущем компьютере его нет.

## Проверки и скорость

```powershell
.\.venv-cpu\Scripts\python.exe -m pip install -r requirements-dev.txt
.\.venv-cpu\Scripts\python.exe -m pytest tests -q
.\.venv-cpu\Scripts\python.exe scripts/benchmark_inference.py --test-csv ../test/test/test.csv --images-dir ../test/test/images --reference ../submission.csv
```

Замер сохраняет загрузку модели, первый прогноз, медиану и p95 следующих запросов
в `outputs/benchmark.json`. HTTP и очередь в этот замер не входят.
Сервис по умолчанию использует четыре потока PyTorch.

На Ryzen 5 5500U (CPU, четыре потока, 10 фото) проверенная модель показала:
загрузка весов 4,01 с, медиана последующих прогнозов 1,99 с, p95 2,05 с.
Это небольшой последовательный замер, а не гарантия для любого оборудования
и потока запросов. [Полный замер](validation/benchmark_cpu.json).

Проверено 82 автоматическими тестами на Python 3.12 и согласованном окружении.
Настоящий HTTP-сервер обработал две фотографии за 2,19 и 2,25 с, вернул XML и
сохранил историю после перезапуска процесса. [Отчёт](validation/service_smoke.json).
Окружение проверки: [validation/environment_cpu.txt](validation/environment_cpu.txt).

## Сдача и работа в команде

Окончательный код — в выданном GitLab: рабочая ветка → Merge Request → `main`.
Нужны код, зависимости, инструкция, локальные метрики и доступ к весам.
Отдельно сдаются `submission.csv` и презентация PDF до 20 МБ.
Перед сдачей ещё нужны проверка Docker, результат скрытого теста на платформе,
презентация и проверка финального содержимого GitLab.

Ноутбук содержит снимок кода. После изменения обучения пересоберите его:
`python scripts/build_kaggle_bundle.py --notebook-only`. Для пересборки датасета
уберите `--notebook-only`. Токен GitLab в Kaggle не нужен.
