# Историческая инструкция: первый запуск на Kaggle

> Это ранний эксперимент. Для выбранного Attention518 используйте [актуальный README](../README.md), разделы воспроизведения и повторного обучения.

## Обновлённый прогон v2

Импортируйте `../kaggle_launch/postcode_kaggle_v2.ipynb` вместо старого ноутбука.
Подключите прежний приватный датасет, включите GPU T4 ×2 и Internet, затем Run All
или Save Version → Save & Run All. Код уже встроен; дополнительные архивы результатов
или модели в Input не требуются. Перед загрузкой нового файла дождитесь окончания.

Сравниваются DINOv2 ViT-B/14 при 392 и 518 пикселях с уточнёнными настройками SVR.
Каждая GPU обрабатывает отдельное разрешение. При одной GPU варианты запускаются
последовательно. Регрессоры переобучаются, веса энкодера фиксированы.
Проверка на прежних групповых folds; публичный рейтинг в выборе модели не участвует.
В предварительном локальном исследовании настройки при 392 пикселях дали MAE 8,08
вместо 8,98; это не обещание такого же балла на скрытом тесте.

Результаты v2: `postcode_output_v2/submission.csv`, `postcode_results.zip`,
`postcode_model.zip`, `kaggle_run.log`. `comparison.json` содержит сравнение разрешений.
CSV и модель на верхнем уровне относятся к одному выбранному варианту. Для анализа
передайте архив результатов и лог; модель сохраните для сервиса.
Сборка v2: `python scripts/build_kaggle_bundle.py --notebook-only --improved`.

## Исходный прогон

Нужны два готовых файла из соседней с репозиторием папки `kaggle_launch`:
`postcode_dataset.zip` (716 обучающих и 307 тестовых фотографий) и
`postcode_kaggle.ipynb` (ноутбук со встроенным кодом).

Обновлённый ноутбук включает `validation/folds_kaggle.csv` из первого успешного
запуска и передаёт его через `--folds-csv`. Новые эксперименты используют те же
пять частей проверки, даже если версия scikit-learn отличается. Этот CSV входит
в проверку SHA-256 встроенного кода; отдельно загружать его в Kaggle не нужно.

1. **Загрузите данные.** На Kaggle создайте новый Dataset из `postcode_dataset.zip`.
   Оставьте доступ **Private**. Дождитесь обработки архива. В датасете должны появиться
   папки `train` и `test`; их не нужно переименовывать. Неполную копию теста из `baseline`
   загружать не нужно.
2. **Импортируйте ноутбук.** Создайте Notebook и выберите импорт файла
   `postcode_kaggle.ipynb` через меню File / Import Notebook. Через Add Input прикрепите
   свой приватный датасет. Доступ к GitLab и токен в ноутбуке не нужны.
3. **Включите GPU и Интернет.** В настройках ноутбука выберите GPU T4 ×2, если этот
   вариант доступен, и Internet — On. Интернет нужен для загрузки предобученных весов.
   Одна доступная GPU тоже подходит. Ноутбук покажет модели GPU и версии библиотек;
   переустанавливать PyTorch вручную не нужно.
4. **Запустите все ячейки.** Нажмите Run All. Ход выполнения печатается под ячейкой
   запуска. Для сохранённого фонового запуска используйте Save Version → Save & Run All
   и дождитесь завершения этой версии. Метрики и артефакты нового эксперимента
   появятся после выполнения.
5. **Скачайте результат и сообщите о завершении.** Скачайте `postcode_results.zip` и
   `kaggle_run.log` по ссылкам последней ячейки и передайте их для анализа. Сохраните
   также `postcode_model.zip` и `submission.csv`. В сохранённой версии файлы доступны
   во вкладке Output, папка `postcode_output`. Если произошла ошибка, скачайте
   `kaggle_run.log` из упавшей ячейки либо вкладки Output и пришлите его или полный
   текст ошибки. Повторять запуск вслепую не нужно.

Если настройка Internet или GPU недоступна, отправьте текст сообщения Kaggle.
Не публикуйте датасет или ноутбук: материалы соревнования остаются приватными.
Перед отправкой CSV на платформу проверьте завершение запуска, локальные метрики
и наличие ровно 307 уникальных ID. Результат платформы относится к скрытой тестовой части.

## Как обновить пакет после изменения кода

В корне репозитория:

```powershell
python scripts/build_kaggle_bundle.py
```

Скрипт использует только стандартную библиотеку Python. Он читает исходные данные
из соседних `train` и `test/test`, проверяет количество строк и ID, создаёт архив
данных и две одинаковые копии ноутбука: в `notebooks` и `../kaggle_launch`.
Исходные изображения и CSV не изменяются. В ноутбук попадают только
`run_experiment.py`, `predict_bundle.py`, Python-файлы `postcode_ml`, `requirements.txt`
и явно разрешённый `validation/folds_kaggle.csv`.

Если изменился только код, архив фотографий можно не пересобирать:

```powershell
python scripts/build_kaggle_bundle.py --notebook-only
```

После этого импортируйте **новую** копию ноутбука. Установленный датасет можно
оставить прежним. `code_manifest.json` и метаданные ноутбука содержат SHA-256 исходников;
ноутбук проверяет эти суммы перед запуском. В выводе будет идентификатор сборки.
